# FSD-04｜每週七日全勤與乘車券（v0.1，產品規則已核定）

**範圍與依據**：六人內部展示版；依 [PRD 最新版](../PRD/智行遊移_PRD_v0.1.md) §5.1–5.3、§7–8 與 P07–P10、P21–P22。接收 FSD-01 的每日有效步數及第三點領取結果、FSD-02 的固定 `memberId` 與當前 `sessionId`；只發模擬乘車券，不連接正式 yoxi 券庫、車資或核銷。修訂後尚未執行複審或實作驗證。

| 契約項目 | 定義 |
|---|---|
| 責任與週期 | 對每個 `sessionId＋memberId＋Asia/Taipei 活動週`，判定週一 00:00 至週日 24:00 的七個任務日是否各達 6,000 **有效步數**；週一獨立開新輪，不採任意連續七天，也不等待上週領券。每日達標紀錄與每日點數領取分開。 |
| 輸入 | FSD-02 驗證的 `memberId`、當前 `sessionId` 與共用情境時間；FSD-01 同場次產出的各日有效步數、資料同步狀態及週日第三點已領事件／狀態（含「全部領取」）。乘車加成由 FSD-01 統一計算，本積木不得另算或重複加乘。 |
| 判定與截止 | 七日皆達 6,000 有效步數，**且該週週日第三點已領取**，才自動發一張週券，不設另行領券按鈕。週日第三點最晚下週一 24:00 前領取；其餘各日步數補同步仍各自受 D+1 日 24:00 截止限制，不可在下週一補齊已逾期的週一至週五。缺資料且仍可補同步時標「待同步」；截止後未達標則無該週全勤券，但其他日點數不受影響。 |
| 延遲補算 | 週日第三點先領、之後合法補同步才使七日全勤成立時，在全勤確認時自動補發並提示，不要求重領第三點；若全勤先成立、週日第三點尚未領，於期限內領取時發券。補同步只影響其歸屬日／週，不改新週進度；已逾期的歷史修正不參與發券。 |
| 產出與資料擁有者 | 共享端保存 `{sessionId, memberId, 活動週 ID, 七日達標狀態, 週日第三點狀態, 發券狀態}` 與唯一券紀錄。券面額 NT$50，成功入帳時以共用情境時間記錄 `issuedAt`，固定 `expiresAt = issuedAt + 30 天`，最低車資 NT$150（含）；另存真實伺服端時間作稽核，不參與模擬效期計算。介面明示情境入帳與到期時間；僅展示模擬獎勵，不宣稱可在正式 yoxi 使用。 |
| 權限與防重 | 成員只能查看自己在當前場次的週進度與乘車券，不能自行寫入全勤或券紀錄；管理者僅依既定展示場次管理權限準備情境。共享端依已驗證身分重算資格；發券受控提交須讀取並核對最新 `sessionId` 與權威情境時鐘版本，以 `{sessionId, memberId, 活動週 ID, 週全勤券}` 作唯一發券鍵。同週重算、刷新、重送與多裝置並發都只產生一張券；已入帳券的 `issuedAt`／`expiresAt` 不因關閉提示、重試或情境時間推進而改寫，時間推進只改可用／過期狀態。 |
| 介面與失敗 | 個人任務顯示「本週已達標 X／7 天」、週一至週日格子及上一週待結算狀態；券入帳後在獎勵頁可查看券面額、最低車資、到期時間。符合資格並確認發券成功時，顯示恭喜與鼓勵文字及「查看乘車券」。第三點已領但發券未完成時須保留持久待結算狀態；共享端在合法資料補同步、領點完成及重連重讀時可重跑判定，直到同一唯一鍵成功入帳或確認不合資格。處理中、斷線或失敗時不得顯示「已入帳」。 |

**最小驗收**：週一至週日各 6,000 有效步數＋週日第三點已領，只發一張券；週三至下週二七日達標不合併。週日第三點未領時不發，期限內逐點或「全部領取」含第三點時發；下週二 00:00 才領則不發。週日第三點已領、週日截止前合法補同步週六步數使全勤成立時自動補發；週一試圖補同步已逾期的週五資料不能發。一般單日領第三點不發週券；車資 NT$149 不符合使用門檻、NT$150 符合（僅驗證模擬券規則，不進行真實核銷）。同週重試、雙裝置同時觸發僅一張；推進情境時間至 `expiresAt` 前／後可見可用／過期狀態，但券的 `issuedAt`／`expiresAt` 不重設；新週進度獨立。對應 P07–P10、P21–P22。

**待決問題**：展示券效期時鐘已由產品負責人核定為共用情境時間；實際券核銷與正式 yoxi 串接不在首版。技術複審仍需確認共享端防重發券的提交方式，不得自行改動券面條件。
