# FSD-01B｜Firebase 今日有效步數與領點薄片（提案契約）

> **已被取代（2026-10-01）**：資料格式與 Rules 由 [FSD-01C](FSD_01C_每日步數規則收斂與昨日補同步補領.md) 取代（新場次單一格式，不遷移）。本文僅保留為歷史紀錄。

狀態：Architect、QA、Security Reviewer 已檢視；本機程式與 Rules Emulator 通過。雲端 Rules 尚未由產品負責人審核／發布，真實跨裝置驗證未完成。僅適用六人內部展示版，不代表完整 FSD-01。

| 契約 | 定義 |
|---|---|
| 責任 | 在既有登入與目前場次下，共享本人今日模擬步數、一次模擬乘車完成狀態、有效步數與逐點／全部領點結果。 |
| 輸入 | Auth UID 對應之固定 memberId、唯讀 `demo/current`、本人步數更新、模擬乘車完成命令與領點命令。步數只可持平或增加；乘車僅可由未完成轉為已完成一次。 |
| 計算 | `effectiveSteps = floor(rawSteps × (rideCompleted ? 1.5 : 1))`。門檻 2,000／4,000／6,000；逐點依序，全部領取原子更新至當前已解鎖最高點。 |
| 資料擁有者 | `dailySteps/{sessionId}/members/{memberId}/days/{taskDate}`。Firestore transaction 原子讀寫；Rules 驗 UID/member/session/clock/taskDate、欄位白名單、步數單調、乘車狀態單向、有效步數與領點轉移。只開放本人 get/create/update，拒絕 list/delete／跨帳號。 |
| 輸出 | 當日原始／有效步數、乘車模擬狀態、已領點數與共享確認狀態。乘車明示為模擬行程，不連 yoxi 訂單；Points 不可兌換。 |
| 失敗／重試 | 交易失敗、離線或情境版本變更時不得顯示成功；先由伺服器重讀狀態再重試。重複乘車及領點命令不得重複增加狀態。 |
| 依賴／邊界 | 依賴 FSD-02 Auth／mapping／`demo/current`。本薄片僅涵蓋當前任務日，不含昨日補同步、可稽核點數帳本、事件發生時間及團隊重播；不可據此宣稱已完成 FSD-01／03／04。 |
| 驗收 | 無乘車時 4,000→有效 4,000；乘車完成後 4,000→6,000；第二次乘車不再疊加；三點必須依序，全部領取一次入帳；下修、跨 UID、錯場次、錯日期、錯 clockVersion、非法乘車狀態與重複領點由 Rules 拒絕。 |

**安全限制**：步數與乘車均由成員自行提供模擬資料。Firebase Auth＋Firestore Rules 保護資料範圍與狀態轉移，但不提供真實訂單驗證或反作弊；不是正式 yoxi 移動／獎勵服務。

**本機資料相容**：Rules 保留 FSD-01A 七欄文件讀取；本人下一次合法更新可將該文件升級為新欄位形狀。未清除或重設任何雲端文件。Emulator 測試含舊形狀升級案例。

**後續交接**：FSD-04 需讀取每日有效步數與週日第三點狀態；FSD-03 仍需步數片段、乘車完成時點及穩定事件順序。本薄片暫不提供這些歷史事件。
