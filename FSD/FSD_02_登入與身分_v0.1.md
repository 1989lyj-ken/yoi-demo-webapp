# FSD-02｜登入與身分（v0.1，產品規則已核定）

**範圍與依據**：六人內部展示版；依 [PRD 最新版](../PRD/智行遊移_PRD_v0.1.md) §3.1–3.2、§6.3（僅推薦身分銜接）、§8 與 P14、P16–P18、P26。只定義展示身分、場次與授權契約，不建立真實 yoxi 會員串接、公開註冊或 Firebase 專案。Firebase Authentication／Firestore 是 PRD 首選技術，尚未部署；修訂後尚未執行複審或實作驗證。

| 契約項目 | 定義 |
|---|---|
| 責任 | 讓六名展示成員用各自帳密進入同一 web app；為其他積木提供穩定成員 ID、一般成員／管理者角色及登入狀態。管理者是六名成員之一，其應用內角色不同於 Firebase 專案管理權限。 |
| 輸入 | 電子郵件、密碼；受管理身分服務回傳的已驗證帳號識別；由產品負責人預先核准的展示帳號名單及角色對應。正式展示信箱可後補，開發測試帳號須與正式展示帳號分開。 |
| 輸出 | 固定 `memberId`（成員資料歸屬主鍵）、受保護的 `role`、當前展示場次版本 `sessionId`、登入／登出／權限不足狀態；提供給步數、團隊、獎勵及管理積木。暱稱與電子郵件只供顯示／登入，不作步數或獎勵資料主鍵。 |
| 流程 | 開啟展示入口→輸入帳密→身分服務驗證→確認帳號在展示名單中→載入對應 `memberId` 與角色→進入 web app。無登入或驗證失敗時不得讀寫共享資料；登出後返回登入畫面。展示介面不提供公開註冊或自助忘記密碼流程；忘記密碼由產品負責人在身分服務中協助重設。 |
| 授權邊界 | 共享端以身分服務驗證的帳號識別查受保護對應，取得固定 `memberId` 與 `role`，並確認其屬於當前 `sessionId`；不得信任前端傳入的身分、角色或場次。一般成員可寫自己的模擬步數、行程及個人領取命令；可讀自己的資料和目前同隊成員允許共享的步數／團隊進度。只有管理者可推進共用展示時間、準備情境資料或重設指定場次；代為準備隊員模擬步數／乘車資料須驗證目標成員與場次並留下操作者、前後值及時間稽核，不授予代替成員領點的權限。（**2026-10-03 FSD-02C 裁決：首版不做代填與停用移出**，展示資料由重設場次＋各成員自行操作達成；本句保留為後續版本的設計約束。）前端隱藏按鈕不是權限控制。 |
| 狀態與異常 | 帳密錯誤、未在名單中、停用帳號、連線失敗各給可理解提示，不洩漏其他成員資料。無網路時不能把未驗證登入或未保存操作顯示為成功；重連後重新取得身分與共享狀態。密碼及管理金鑰不寫入 HTML、原始碼、PRD 或共享資料。 |
| 依賴與交接 | 此積木先於步數、團隊、獎勵等共享功能；其餘積木只接收共享端可驗證的 `memberId`、角色與當前 `sessionId`，不自行用暱稱或信箱判定身分。更換展示信箱時保持原 `memberId` 對應，避免資料改掛；對應變更由受控管理流程執行。展示場次資料與帳號身分分離：管理者重設指定場次時，以受控提交啟用新 `sessionId`；推進情境時間也以受控提交更新權威時鐘與版本。領點、乘車加成、組隊及發獎提交須讀取當前 `sessionId`／時鐘版本，拒絕重設或時間推進前取得的過期狀態。舊版展示資料不再進入當前畫面或防重鍵，不刪帳號或改變 `memberId`，也不影響其他場次。 |

**最小驗收**：六個不同帳號各綁定固定 `memberId`；指定展示場次起始時六人皆未組團，每人可輪流建立隊伍並邀請其他成員；重設該場次後產生新 `sessionId`、固定身分不變且可換人當組長，舊版資料不串入新版；同一場次內仍遵守每人每週一隊。六人也能輪流測試模擬推薦人／被推薦人；重設場次推薦資格不建立新帳號。A 無法改 B 的步數，同隊時可讀允許共享的步數；一般成員無法重設場次或倒退時間；未登入／未核准帳號直接呼叫共享資料遭拒；前端偽造 `memberId`／`role`／`sessionId` 不能越權。對應 P14、P16–P18、P26。正式信箱尚未提供，不能宣稱六個正式展示帳號已完成。

## 決策紀錄

- 2026-09-29：六人可在隔離的展示場次中輪流當組長，也可輪流測試模擬推薦人／被推薦人；場次重設不改帳號、密碼或固定成員 ID。場次重設的資料範圍與確認操作由後續團隊／展示管理積木具體定義。
- 2026-09-29：展示版不開發自助忘記密碼流程；由產品負責人在身分服務中協助重設。未來正式版密碼控管沿用當時 yoxi 的既有方式，本展示版不另設計其細節。
- 2026-09-29：同一展示場次的共用情境時間只可由管理者向前推進；要重演則重設指定場次並啟用新 `sessionId`，固定 `memberId` 不變。

**待提供資料（非規格決策）**：六個正式展示信箱與其中哪一個綁定管理者；實際帳號建立、專案權限、計費與部署均由產品負責人另行安排。
