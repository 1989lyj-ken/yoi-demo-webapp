# 公開測試版：評估與後續積木規劃

**狀態**：評估草案（2026-10-06），尚未排程。各積木開發前須依 AGENTS.md 流程（契約 → Architect → 實作 → QA／Security）。

## 目標
知道連結的人都能進入，**一個人**就能體驗平台全部功能：步數與領點、乘車加成、昨日補同步、七日全勤與乘車券、組隊與團隊寶箱、隊名、推薦新戶、通知、地圖與天氣、遊玩指南。

## 現況為什麼不能直接公開
| 現況（內部展示版） | 公開時的問題 |
|---|---|
| 6 個固定帳號，由產品負責人建立帳號與 `membersByUid` 對應 | 訪客無法自行進入 |
| 全場共用一個時鐘 `demo/current`，只有管理者能推進 | 訪客無法自己「過一天」；任何人推進都會影響所有人 |
| 組隊至少 2 人、推薦需要另一位新戶 | 一個人無法體驗團隊寶箱與推薦獎勵 |
| 全勤需真的經過七天 | 無法快速體驗 |
| Rules 只防內部成員，沒有濫用與成本防護 | 公開後可能被大量寫入、產生費用 |
| 外部服務以內部非商業使用評估（OpenStreetMap 圖磚、Open-Meteo） | 公開流量與用途可能不符條款 |

## 核心設計建議
**每位訪客一個「個人沙盒場次」**：訪客登入後自動取得自己的場次與時鐘，只有自己能推進，資料與他人完全隔離。所有「快速體驗」都建立在個人時鐘上，因此不需要讓 Rules 開放寫入過去的日子，也不會影響其他人。內部展示版維持共用場次與管理者時鐘。

## 後續積木（建議順序）
| 編號 | 積木 | 內容 | 改 Rules | 規模 |
|---|---|---|---|---|
| PB-00 | 環境分離 | 公開版另開 Firebase 專案與 Hosting 網址；建置旗標切換；公開版不含管理頁、不含內部帳號 | 新專案 | 小 |
| PB-01 | 訪客登入 | Firebase 匿名登入（免註冊）；首次進入自動建立成員資料與暱稱（例如「訪客 4821」，可改名）；清除瀏覽器即重新開始 | 是 | 中 |
| PB-02 | 個人沙盒場次與個人時鐘 | `demo/current` 改為每位訪客自己的場次文件；所有 Rules 的場次／時鐘檢查改讀「自己的場次」；選單提供「快轉到明天 09:00」「快轉到下週一」「重新開始體驗」 | **大幅** | 大（最關鍵） |
| PB-03 | 一鍵體驗情境 | 在個人時鐘上自動跑：「七日達標」（自動補 6,000 步並逐日快轉，得乘車券）、「團隊達標」、「推薦成功」 | 視 PB-02 | 中 |

| PB-05 | 模擬推薦新戶 | 產生一位模擬新戶綁定你的推薦碼，並可「模擬新戶首趟搭乘」，雙方推薦券入帳 | 是 | 中 |

| PB-07 | 濫用與成本防護 | Firebase App Check；每位訪客寫入頻率與文件數上限；預算警示；匿名帳號與沙盒資料定期清除（Firestore TTL） | 是 | 中 |
| PB-08 | 隱私、條款與聲明 | 公開版隱私說明（定位、天氣、匿名資料保存期限）、使用條款、「模擬資料、非正式 yoxi／和泰 Points」聲明；必要時同意流程 | 否 | 小 |
| PB-09 | 外部服務合規 | 地圖圖磚改用允許公開流量的供應商或自架；天氣改中央氣象署（需後端代管金鑰）或 Open-Meteo 付費方案；字型與圖示授權確認 | 否（可能需後端） | 中 |
| PB-10 | 回饋與觀察（選做） | 意見回饋入口、匿名使用統計（需另行同意） | 視方案 | 小 |

## 與目前內部版的關係
- 內部版第 14 點（管理頁「自動七天」）可先做，供錄 Demo；不改 Rules。
- 公開版的「成員自己快速體驗七日達標」由 PB-02＋PB-03 提供，不在內部版的共用場次上實作（避免改動共用場次的資料完整性）。
- PB-02 會改寫大部分 Rules 的場次檢查，建議在內部版功能凍結、Demo 錄製完成後再開始，並以 Emulator 全套測試與 mutation 重跑驗證。

## 需要產品負責人決定（排程前）
1. 公開版是否另開 Firebase 專案（建議是）。
2. 訪客資料保存多久（建議 7 天未使用即清除）。
3. 公開版是否算商業用途（影響地圖與天氣服務選擇）。
4. 模擬隊友與模擬新戶的數量、名稱與步數設定。

## 產品負責人回覆（2026-10-06）
- 公開版**另開 Firebase 專案**。
- 訪客資料保存 **7 天**：以「最後一次使用」起算；7 天內有再進來就重新起算、資料保留；超過 7 天沒進來才清除（下次進入等於新訪客）。
- 使用場合：職訓局 AI PM 專班發表會（同學、老師、評審）；之後和泰集團 AI 黑客松交主辦單位體驗測試。
- 模擬隊友與模擬新戶的設定 OK。

## 補充評估（2026-10-06）
- **商業用途判斷**：專班發表會屬教育、非營利展示，一般可視為非商業。黑客松由企業主辦、目的是評估產品概念，屬灰色地帶，建議比照商業用途處理：天氣改用 Open-Meteo 付費方案（或事先向 Open-Meteo 確認）、或改中央氣象署（需小型後端代管金鑰）；地圖圖磚流量小，但宜改用允許此類用途的圖磚服務。以上非法律意見，正式提交前請再確認各服務條款。
- **展示版的模擬隊友能否直接用**：純展示版的「模擬一位隊友加入」只存在本機、隊友步數是固定數字，沒有走共享資料的團隊進度、結算與寶箱規則，因此不能直接搬到以 Firebase 為後端的公開版；在公開版要讓機器人隊友真的推動團隊進度與寶箱，仍需 PB-04 的規模。
- **替代架構（建議納入排程前比較）PB-A「本機模擬後端」**：公開版沿用現在的正式畫面，但把資料層換成瀏覽器內的模擬實作（不連 Firebase）。優點：不需改寫 Rules、沒有濫用與雲端費用、資料自然只在訪客自己的裝置、7 天清除可直接用本機到期處理；個人時鐘、模擬隊友、模擬新戶都在本機實作，規模比 PB-01／02／04／05／07 合計小。缺點：無法展示「跨裝置／多人即時同步」，且現有服務類別需抽出介面（中大型重構）。發表會與黑客松以單人體驗為主時，建議優先評估此方案。

## 產品負責人裁決（2026-10-06，第二次）
- 訪客資料改為 **3 天未使用即清除**（以最後一次使用起算；3 天內有進來就重新起算）。
- **採用 PB-A「本機模擬後端」**：公開版沿用正式畫面，資料全部存在訪客自己的瀏覽器、不連 Firebase 資料庫；目標是以最少開發量模擬體驗全部功能。原 PB-01、PB-02、PB-04、PB-05、PB-07（Firebase 版）不做，改為下列積木。

## 公開版積木（PB-A 版，取代上方 Firebase 版清單）
| 編號 | 積木 | 內容 | 規模 |
|---|---|---|---|
| PA-00 | 環境 | 另開 Firebase 專案，**只用 Hosting**（不開 Firestore／Auth）；建置旗標 `public` 切換資料層；公開版不含管理頁與內部帳號 | 小 |

| PA-05 | 模擬新戶 | 「產生模擬新戶並綁定我的推薦碼」「模擬新戶首趟搭乘」，雙方推薦券入帳 | 小 |
| PA-06 | 訪客進入 | 免登入、自動暱稱（可改）；首頁「開始體驗」 | 小 |
| PA-07 | 導覽與體驗清單 | 首次導覽；功能體驗清單逐項打勾 | 小 |
| PA-08 | 聲明 | 模擬資料、非正式 yoxi／和泰 Points、**非商業用途**、資料只存在本機且 3 天未使用清除 | 小 |

- **建議順序**：PA-00 → PA-01 → PA-02 → PA-03 → PA-06 → PA-04 → PA-05 → PA-07 → PA-08／09。PA-01 是唯一較大的重構，完成後其餘多為組裝。

## 天氣與地圖（免費服務能否繼續用）
- 在公開版寫「禁止商業用途」約束的是**訪客**，不會改變**我們自己**使用服務的性質。條款看的是營運方的用途：專班發表會屬教育展示，可繼續用免費服務；黑客松是交給企業評估產品概念，仍屬灰色地帶，聲明本身無法解決。
- OpenStreetMap 圖磚政策重點是流量與出處標示（非商業與否）；發表會與黑客松的小流量、保留出處即可，但不得大量下載或壓力測試。
- **建議（最省事）**：公開版天氣預設用「**模擬天氣**」（依個人時鐘產生，晴／陰／雨／雷雨輪替），完全不連外部天氣服務，也與「模擬體驗」一致；需要真實天氣時再另行評估付費方案或事先詢問 Open-Meteo。
- 以上不是法律意見；正式提交黑客松前，建議寄信向 Open-Meteo 確認用途。
