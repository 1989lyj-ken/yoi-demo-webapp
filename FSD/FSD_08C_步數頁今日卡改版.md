## 產品負責人裁決（2026-10-07）

1. 進度條上的鞋子不固定在起點，而是浮在軌道上方，隨步數往右移動（取代設計稿「起點固定是鞋子」）。0 的位置改成小圓點。
2. 位置說明兩句話獨立成一張小卡，放在「今日」「本週」「昨日」三個頁籤最下方，一直顯示（不再等開啟定位才出現）。
3. 慶祝彈窗（S6～S8）與 S1～S5 同批完成、同批部署。
4. 昨日卡不放進度條，只列「昨天走了 N 步」「可以補領 N 點」「搭車加成」，加上「補領 N 點」按鈕（樣式同今日的領取按鈕）。補同步的輸入框暫時維持原樣。

## 規則

- 「步數」一律指有效步數：實際步數 × 1.5（搭車後）取整數；沒有其他計算（`effectiveStepsOf`）。
- S3 一句話、S5 搭車列說明、S6 彈窗小字與按鈕：依 handoff 的表格，純函式在 `src/daily/today-card.ts`。
- S4：沒有可以領的點數時，按鈕整顆不顯示；按一次全部領完（`claimAll`）；不加光暈。
- S6：只有伺服器在本次 transaction 確認的搭車才跳彈窗；未確認或失敗不跳。按遮罩不會關閉；Escape 等同「知道了」（只關閉、不領點）。
- S7：只播一次，約 1.5 秒；`prefers-reduced-motion: reduce` 時直接顯示播完的畫面。
- S8：地圖大數字顯示有效步數，搭車後下面多一行「搭了 yoxi，步數變 1.5 倍・實際走了 N 步」；彈窗跳出時卡片已是新狀態。
