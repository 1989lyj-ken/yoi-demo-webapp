# FSD-03｜團隊共享（v0.1，已核定規則）

**範圍與依據**：六人展示版；依 [PRD 最新版](../PRD/智行遊移_PRD_v0.1.md) §3.2、§6.1–6.2（僅寶箱資格交接）、§8 與 P09、P11–P13、P16–P20、P23、P25–P26。涵蓋建隊、入隊、共享進度、退團與隊長；不定義寶箱抽獎、開箱或「推薦新戶」獎勵。產品規則已核定，主動解散權限另待確認；修訂後尚未執行複審或實作驗證。

| 契約項目 | 定義 |
|---|---|
| 責任與身分 | 持續存在的隊伍實體以 `sessionId＋teamId` 區分，現有成員與隊長跨週保留；每週貢獻、達標及獎勵資格另以 `sessionId＋teamId＋活動週 ID` 區分。成員以 FSD-02 的固定 `memberId` 識別，不以暱稱／信箱識別。場次起始六人未組團；每人可在不同場次版本輪流當隊長。 |
| 操作輸入 | FSD-02 驗證的成員與當前 `sessionId` 發起建立／取消招募、分享／輸入隊伍邀請碼、加入、本人退團、隊長轉讓；FSD-01 提供含 `sessionId`、新增量、發生時間及同步時間的原始步數片段，以及當日首趟已完成乘車的 `completedAt`／穩定事件 ID；共用情境時間決定 Asia/Taipei 活動週。一般成員不可直接寫他人的步數或隊伍總量，隊長不可移出其他成員。 |
| 隊伍狀態 | 1 人為「招募中」；第 2 人加入時成團，2–5 人為「進行中」；退團後剩 1 人為「暫停」，補回第 2 人恢復；無人時「封存」。第 6 人不得加入。招募中不占用當週正式隊伍資格，但一人同時只可建立一個招募中隊伍；要加入他隊須先取消自己的未成團招募。 |
| 貢獻與週目標 | 每週一 00:00–週日 24:00，目標固定 300,000 有效步數。隊伍、現有成員與隊長跨週持續保留，只有各週貢獻與達標紀錄分開重算；不因週一到來而自動解散或換隊。只計「已成團、隊伍未暫停、本人在隊期間」發生的步數片段；按成員＋日期合計合資格原始步數，當日乘車加成後取整數部分。片段先以 `occurredAt` 作基礎貢獻；首趟合資格乘車完成時，當日前已合資格片段產生的加成**增量**才以 `completedAt` 生效；搭乘後新增的合資格片段按已生效加成計入。同一日第二趟不再產生加成。完成時若成員已退隊或隊伍暫停，不新增該時刻的團隊貢獻；既有基礎貢獻仍保留。昨日補同步片段的 `occurredAt` 必須落在其 `taskDate` 內，不能以今日 `syncedAt` 判斷歸屬；合法補同步重播片段與乘車事件時，也不得把因乘車加成而首次達標的時點倒推至 `completedAt` 前。個人任務不受團隊暫停影響。 |
| 會員與隊長 | 每人每活動週只可貢獻給一個正式隊伍；留在原隊者下週自動延續。退團僅能由成員本人發起並立即生效；隊長不得主動移出其他成員。退團當週不可加入或重回任何正式隊伍，下週一才可重新組隊；因此若想在下週一加入別隊，須於本週日結束前先退出原隊。未達標隊伍可補入合資格者，只計加入後片段。隊長退出時由最早加入的現有成員接任；現任隊長可轉給現有成員，原隊長仍是一般成員；同時退團／轉讓只產生一位有效隊長。 |
| 共享輸出 | 當前成員可看到彼此今日原始／有效步數、乘車加成來源、本週個別合資格貢獻、歷史成員已保留貢獻、隊伍總量、目標進度、隊長、最後同步時間與「同步中／已同步／未同步」。隊伍總量由共享端依合資格片段重算，不接受手機直接提交總量。 |
| 歷史異動 | 共享端保存不可被一般成員覆寫的成團、入隊、退隊、暫停／恢復、隊長轉讓／接任與封存事件；每筆含 `sessionId, teamId, eventId, effectiveAt, serverRecordedAt, actorMemberId, eventOrder`。會員／隊伍事件的 `effectiveAt` 由共享端權威情境時間賦值；步數片段、已完成乘車與團隊事件在同一場次內使用共享端穩定的 `eventOrder` 比較相同時點先後，重送事件 ID 不重複入帳。歷史補同步依片段 `occurredAt`、乘車 `completedAt` 與當時事件狀態還原隊伍／會員資格，不能只看目前名單。 |
| 結算交接 | 首次合資格達 300,000 時，以週紀錄保存達標時點、當時合資格成員名單及判定依據，交寶箱積木發資格；本積木不抽獎。合法次日補同步按步數發生時間歸回原週與當時會員狀態；若歷史達標時點提前，既有寶箱資格不撤銷，新增合資格者可補發，每人每週至多一箱。結算與資格交接須有穩定唯一鍵及可重跑狀態，避免已達標卻漏發資格。 |
| 同步與失敗 | 共享資料變更後即時訂閱，不設五秒等待；正常雙端前景連線的 A 提交至 B 顯示 95% 小於一秒是**待實測目標**。寫入未確認不得顯示已同步；斷線顯示最後同步資料與時間，重連後以共享端狀態為準。加入、退團、轉讓及達標判定的受控提交須核對最新 `sessionId` 與情境時鐘版本，處理同時操作，避免超員、雙隊長、重複貢獻或重複發資格。 |

**介面與驗收**：建立／取消招募與輸入隊伍碼；招募中、進行中、暫停、封存狀態清楚可見。退團前提示「既有貢獻保留、當週不能換隊、未取得的寶箱資格可能失去」。測試 1→2 人成團、5→6 人拒絕、一人第二個招募遭拒、299,999→300,000、退團／補員／暫停、隊長接任與轉讓、週一隊伍 ID／成員／隊長保留但週貢獻另起、週日補同步依歷史事件還原、同情境時間事件穩定排序、晚間乘車使團隊跨 300,000 時不回溯至白天且名單依乘車完成時刻判定、不同裝置相互看到步數與斷線恢復；場次重設不刪帳號、不影響其他場次且不混入舊隊伍。對應 P11–P13、P16–P20、P23、P25–P26。

## 決策紀錄與唯一待決事項

- 2026-09-29：新增模擬步數須保存新增量與發生時間；管理者可指定昨日補同步片段時間。FSD-01 已同步補上片段交接。
- 2026-09-29：隊伍、現有成員與隊長永久跨週保留，直到成員異動或隊伍解散；週一只重置本週貢獻／目標進度。已成團後剩一人者跨週仍維持「暫停」，補足兩人才恢復。
- 2026-09-29：一人同時只能有一個未成團招募；加入他隊前先取消自己的招募。
- 2026-09-29：退團僅由成員本人發起；首版隊長不可主動將隊員移出。隊長轉讓與隊長本人退團規則不變。
- 2026-09-29：產品負責人核定，乘車加成造成的團隊貢獻增量於首趟合資格乘車完成時生效；因加成達標不得倒推到乘車前，寶箱名單依實際達標時點判定。
- **待決**：「隊伍解散」除無成員自動封存外，是否提供現任隊長主動解散操作？若提供，須另定成員同意、歷史貢獻／獎勵及當週換隊資格的處理；本 FSD 暫不納入主動解散操作。
