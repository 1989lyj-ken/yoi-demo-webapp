# FSD-01｜有效步數與每日領點（v0.1，產品規則已核定）

**範圍與依據**：六人展示版；依 [PRD 最新版](../PRD/智行遊移_PRD_v0.1.md) §5.1、§5.2（僅跨積木觸發）、§5.3、§7（僅領點提示）、§8（僅權限／共享）與 P03–P09、P19、P21–P22、P26、P28。本文不定義真實步數匯入、真實行程或 Points 兌換。`sessionId` 為 FSD-02 提供的當前展示場次版本 ID；重設後使用新 ID，固定 `memberId` 不變。產品規則已核定；修訂後尚未執行複審或實作驗證。

| 契約項目 | 定義 |
|---|---|
| 責任 | 對每個 `sessionId＋memberId＋Asia/Taipei 任務日 D`，計算唯一的任務有效步數、解鎖三個每日里程碑、處理逐點／全部領取，並保存可跨裝置讀取的結果與點數紀錄。 |
| 輸入 | FSD-02 提供的已驗證 `memberId` 與當前 `sessionId`；任務日 D 的模擬原始步數（非負整數，僅可持平或增加）；每次增加時的步數發生時間（今日＝共用情境當下；昨日補同步由系統固定為昨日 23:59:59，2026-10-01 修訂）；完成的 yoxi 模擬行程及完成時間；共用情境時間；領取命令 `{任務日, 里程碑 1/2/3 或全部}`。取消／未完成行程不算；行程依完成日歸屬。 |
| 運算 | `有效步數 = floor(原始步數 × (當日有至少一趟完成行程 ? 1.5 : 1))`。第二趟不再疊乘；不增加信用卡限制。達 2,000／4,000／6,000 有效步數分別解鎖第 1／2／3 點，每日最多 3 點；解鎖不等於入帳。 |
| 產出 | `原始步數、有效步數、是否有乘車加成、各里程碑狀態、當日已領／可領點數、補領截止、最後同步時間`；每次增加的差額另存不可重複的原始步數片段 `{sessionId, memberId, taskDate, rawDelta, occurredAt, syncedAt, segmentId, eventOrder}`（FSD-01C 實作為 `events/{seq}`：`segmentId`→每日文件內的 `seq`；`rideId`→`kind='ride'` 事件；跨成員的全場次 `eventOrder` 由 03C 定義），供團隊積木判定入隊／暫停時段。完成乘車另交接 `{sessionId, memberId, taskDate, rideId, completedAt, eventOrder}`；團隊加成增量不得早於首趟完成時間生效。`eventOrder` 為同一情境時點跨步數、乘車與團隊事件比較時的共享端穩定順序。領取成功後產生含 `sessionId`、身分 ID、任務日、里程碑、情境領取時間及伺服端稽核時間的點數帳本紀錄；模擬點數餘額以 `sessionId＋memberId` 歸屬，或由該範圍內帳本推得，不混入舊場次。週任務與團隊積木共用加成規則，不在各畫面另算。 |
| 狀態與期限 | 每個里程碑為「未達標／已達標待前點／可領取／已領取／已逾期」；只有前一點已領且本點達標時，本點才可逐點領取。昨日與今日分區。「全部領取」只處理指定任務日已解鎖且未領的點數，按第 1→2→3 點順序一次完成。D 當日到 D+1 日 24:00 前可補同步及領取；D+2 日 00:00 起不可再因歷史修正發點。 |
| 寫入與防重 | 一般成員只能提交自己在當前場次的模擬步數、行程與領取命令；管理者準備隊員資料須走受控管理操作，驗證目標 `memberId`／`sessionId` 並記錄操作者、目標、前後值與伺服端稽核時間，不能冒用成員身分領點。共享端依 FSD-02 驗證身分與角色，不信任前端指定的 `memberId`／`sessionId`。共享端拒絕低於該成員該日已保存原始步數的更新，包括另一裝置送出的舊值；只對高於已保存值的差額建立一次片段，相同值重送不增加片段。`occurredAt` 須落在 `taskDate` 的 Asia/Taipei 日期內，且不得晚於共用情境當下；`syncedAt` 僅記實際提交稽核時間，不得代替發生時間。領點或更新步數時，在同一受控提交中讀取並核對當前場次版本與權威情境時間，再檢查 D+1 截止及重算資格；以「`sessionId＋memberId＋taskDate＋里程碑`」作唯一入帳鍵。逐點、全部領取、雙裝置連點或重送均不得重複加點；點數帳本與同場次餘額一致更新，成功後回傳共享端確認的最新狀態。 |
| 異常與依賴 | 未連線或寫入失敗顯示「未同步／未入帳」，不得先宣稱成功；重連後重讀共享狀態。次日補同步昨日步數可重新解鎖剩餘點數，但不延長領取期限；單純補領不修改步數。第三點領取事件／狀態須持久交接 FSD-04；若後續發券暫時失敗，不回滾已成功領點，待發券結算可安全重跑。本積木不自行發券。 |

**介面要點**：記步頁分別顯示原始與有效步數；三個里程碑自上而下為累計 1／2／3 點，按鈕標「本次領取 1 點」。未達標暗色不可點；已達標但前一點未領時顯示「請先領取前一點」且不可點；輪到本點時亮色可領；已領標示完成。「全部領取」標明所屬日期。昨日有可補領點數時，固定提醒顯示截止時間；通知與首次進入提示讀同一領點狀態，截止後同步更新。乘車加成達 6,000 時文案寫「任務有效步數達標」，不宣稱實走 6,000。

**最小驗收**：1,999／2,000／4,000／6,000 步門檻；4,000 原始步數＋一趟當日完成行程＝6,000 有效步數；第二趟不疊乘；6,000 步未領餘額不變；未領第 1 點時第 2／3 點不可逐點領；全部領取依序入帳三點，已領一點後全部領取只加兩點；同日步數下修及跨裝置舊值更新均被拒絕；昨日補同步後補領，發生時間跨日或晚於情境當下遭拒；D+2 00:00 拒領；雙裝置同時領同一點只入帳一次；場次重設後同成員同日期可重新演示而不碰撞舊帳本。對應 P03–P09、P16、P19；第三點狀態供 P21–P22 使用。

## 決策紀錄

- 2026-09-29：產品負責人核定模擬原始步數不得下修；不論是否已領點，對已保存的同日數值皆只允許持平或增加。
- 2026-09-29：產品負責人核定逐點須依第 1→2→3 點領取；「全部領取」亦按此順序處理當日所有已解鎖且未領點數。
- 2026-09-29：產品負責人核定每次新增模擬步數記錄新增量及發生時間；管理者可指定昨日補同步片段的發生時間，供團隊判定加入／暫停時段。
- 2026-09-29：產品負責人核定一般成員補同步昨日資料時選擇昨日的模擬發生時間；共享端檢查任務日與發生時間一致。同場次情境時間只可向前，重演另起場次版本。
- 2026-10-01：產品負責人修訂補同步發生時間：成員不再選擇，昨日補同步增加的步數片段，發生時間由系統固定為昨日 23:59:59（Asia/Taipei）；取消管理者預設。今日仍為共用情境當下；乘車固定為今日、等於情境當下，不可補到昨日。此修訂取代 2026-09-29 最後一條決策與上表輸入欄「由成員選擇昨日時間」的描述，並同步修訂 PRD §5.1、§8、P09、P25、D14。
