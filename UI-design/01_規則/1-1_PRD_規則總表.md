## 0. 目標與成功指標

### 一句話

> 走路累積的和泰 Points，即刻折抵 yoxi 車資——家人組隊一起存，不搭車的日子也有打開 yoxi 的理由。

### 1.0 要證明的三件事

| # | 假說 | Demo 要演出來的 |
| :- | :--- | :--- |
| 1 | 走路能成為每天打開 yoxi 的理由 | 今日足跡、記錄一段路、點數進度、已連續 N 天 |
| 2 | AI 能在對的時機把走路的人導回叫車 | 走路中的情境建議 → 叫車確認頁帶入點數折抵 |
| 3 | 家人組隊比個人任務更能維持習慣 | 團隊進度、隊友步數互看、團隊寶箱、邀請 |

### 成功指標

分三層，**越往下越需要真實營運資料**。Prototype 階段只宣稱第一層；第二、三層在簡報中只講「定義與驗證方法」，不宣稱達成值（決策 #75）。

**北極星指標：參與用戶每月的增量叫車趟次**——與對照組相比，多出來的叫車。這直接回答賽題「非叫車互動如何導流成真實叫車」。

#### 第一層：Demo 驗收（10/13 交件前，我們自己能達成）

| 指標 | 目標 |
| :--- | :--- |
| 第 6 章驗收條件通過數 | **第 3.1 節「做」範圍內全數通過** |
| 主流程走通 | 今日足跡 → 記錄這段路線 → 建議卡 → 叫車確認頁帶入點數折抵，**不中斷、不需口頭解釋** |
| 小白測試（10/9–10/12 彩排） | 找 5 位非本領域的人，**至少 4 位不經提示完成主流程** |
| 大字好讀模式 | 主流程在大字好讀模式下同樣走得通 |

#### 第二層：產品指標（試營運，對應第 0 章三個假說）

試營運時保留 **10–20% 用戶不開放此功能作為對照組**，以下指標皆為「參與者 vs 對照組」的差異。

| 假說 | 指標 | 定義 | 成立條件 |
| :- | :--- | :--- | :--- |
| 1 走路成為每天打開 yoxi 的理由 | **非叫車日開啟天數** | 每人每週「沒有叫車、但有打開 yoxi」的天數 | 高於對照組 |
| | 沉默超過 7 天的比例 | 連續 7 天以上沒有任何互動（走路記錄或叫車）的用戶比例 | 低於現況基準 **19.3%**（行程資料中搭車間隔超過 7 天的比例；定義不同，僅作方向參考）|
| 2 AI 能在對的時機把人導回叫車 | **建議卡轉換率** | 回程卡、雨天卡出現後 30 分鐘內叫車的比例，依卡片類型分開看 | 回程卡高於「同距離但未出卡」的散步 |
| | 推播關閉率 | 收到情境推播後關閉通知的比例 | 反向指標，越低越好（`A4`）|
| 3 家人組隊比個人更能維持習慣 | **團隊成員 4 週留存** | 加入團隊者 vs 未加入者，第 4 週仍有走路記錄的比例 | 團隊成員較高 |
| | 團隊週達標率 | 達成 `T2` 的團隊比例 | 用來校正 `T2` 與寶箱成本 |

#### 第三層：商業指標（正式版，回答 ROI）

| 指標 | 定義 | 成立條件 |
| :--- | :--- | :--- |
| **增量叫車趟次**（北極星） | 參與者 vs 對照組的每人每月叫車趟次差 | 顯著為正 |
| **每增量趟獎勵成本** | （點數實際使用 ＋ 券實際核銷）÷ 增量趟次 | **低於每趟毛利**才划算；毛利待和泰提供 |
| 邀請轉換 | 受邀者 註冊 → 活化（首次達標）→ 首次叫車 的各段比例 | 邀請加碼的增量成本一對 100 元（`I1`），看每位叫車新客的取得成本 |
| 點數流通 | 走路點數用在 yoxi 以外（HOTAI購、iRent 等）的比例 | 佐證「準貨幣」論述（KC〈商轉假說〉2B）|

#### 護欄指標（出現就要調規則）

| 指標 | 警訊 | 對應調整 |
| :--- | :--- | :--- |
| 折扣依賴度 | 參與者叫車時使用折抵或券的比例持續上升，但總趟次沒增加 | 代表在補貼原本就會叫的車：調降 `P9` 面額、提高 `R6` |
| 每人每月獎勵成本 | 超出 Show 哥試算的預算區間 | 先調堅持一週面額（`P9`），再調團隊寶箱機率（`R2`）|
| 定位權限拒絕率 | 過高（問卷有 47.5% 在意軌跡追蹤）| 強化隱私說明，檢查 S19 權限說明頁 |

**對外說法**：目標數字沒有依據前不寫進簡報（見 `perplexity建議_評估.md` 第 3.5 節）；簡報講「我們會怎麼證明」，不講「我們會達到多少」。

⚠️ 初賽的評分重心是商業轉化、可行性、技術架構與成本成效（合計約 50%），所以成功指標不能只寫「使用者會不會喜歡」。

## 1. 名詞表

**一詞一義**。左欄是內部代號，右欄是**畫面上必須使用的字**；不要混用。

| 內部代號 | 畫面用語 | 定義 |
| :--- | :--- | :--- |
| 移動足跡 | 今日足跡 | 1.0 的功能總稱；畫面上以「今日足跡」為入口名稱 |
| 團隊寶箱 | **團隊寶箱** | 團隊週達標後，全員各得一次的抽獎 |
| 堅持一週 | **連續 N 天** | **活動**：個人連續 7 天走滿 `P3` 的進度；第 7 天得到一張犒賞券（`P9`）。畫面只顯示「已連續 N 天」|
| 連續達標券（原「超標限時券」）| **犒賞券** | **獎品**：你走出來的。完成堅持一週得到，$50、30 天內可用（`P9`、`R4`、`R7`）|
| 團隊 | **團隊** | 2–5 人的走路小組；畫面一律寫「團隊」，不寫「小隊」「群組」（2026/09/22 由「小隊」改為「團隊」，決策 #81） |
| 點數 | 和泰 Points | 1 點 = 1 元；畫面寫「點」，不寫「NT$」 |
| 步數目標 | 今天的點數 | 進度以「點」表示（`2 / 3 點`），不以步數當進度單位 |
| 大字好讀模式 | 大字好讀模式 | 使用者可切換的介面模式（原名銀髮模式，9/16 更名），**不是預設** |

**不得出現在畫面上的字**：超標、喚回、個人寶箱、小隊、長輩、銀髮、身障者、ETA。

## 3. 範圍

## 4. 規則參數表（單一真相來源）

### 4.1 個人

| 代號 | 參數 | 值 | 備註 |
|---|---|---|---|
| `P1` | 每幾步 1 點 | **2,000 步** | |
| `P2` | 每日點數封頂 | **3 點** | 即走滿 6,000 步 |
| `P3` | 每日目標步數 | **6,000 步** | 健康最佳步數 |
| `P6` | 超標步數去向 | 計入團隊週目標，不再加點 | 決策 #52 |
| `P9` | 堅持一週 | **任意連續 7 天**每天走滿 `P3`，得 **$50 犒賞券**、效期 **30 天**。**連續天數照常往上加，只有「下一張券」的倒數每 7 天重新算**（第 7、14、21⋯天各得一張）；中斷一天才整個歸零 | 決策 #71、#89。第 7 天的券隨 `M4` 達標慶祝一起發，不另跳畫面。原寫「取得後重新計算」會讓第 8 天顯示「已連續 1 天」，等於把努力歸零 |

| `P8` | 進度說明文案 | 進度條下方的**提示句用時間講**：「再走約 15 分鐘，就多 1 點」；步數只出現在 `P7` 的步數行，提示句不寫「再走 N 步」 | 步速約 100–115 步／分；時間比步數、公里更有體感 |

## 6. 功能與驗收條件

### 6.1 記錄與點數

- [ ] 沒按「記錄這段路線」時，步數也由系統計步器全天累積，今日點數進度照常更新（`M2`）
- [ ] 今日足跡點數卡寫明點數自動累積（「手機記下的每一步都自動算點數，不用開著 App」）；記錄結束摘要的點數列顯示今天的點數，不寫「這次存到 N 點」（決策 #101）
- [ ] 還沒連結步數時，今日足跡的主按鈕是「連結步數」，先問步數權限；定位權限等第一次按「記錄這段路線」才問，兩者不同時問（決策 #101）
- [ ] 按「記錄這段路線」後，地圖開始畫軌跡，這段路線的步數與距離即時更新
- [ ] 每累積 `P1` 步，當日點數 +1，進度條同時亮一段，**共 3 段**（`P7`）；小車依步數連續移動
- [ ] 進度條正下方顯示「今天步數 / 6,000 步」；超過 `P3` 後只顯示步數，不顯示分母（`P7`）
- [ ] 今日足跡頁首顯示「今天步數 / 6,000 步」，該頁進度條不重複顯示步數行（`P7`）
- [ ] 提示句用時間表示，不出現步數或公里（`P8`）
- [ ] 當日點數達 `P2` 後不再加點，但步數與距離繼續記錄
- [ ] 封頂後文案：有團隊顯示「今天的點數已存滿，接下來的每一步都會算進團隊」；無團隊顯示「今天的點數已存滿——加入團隊，多走的步數就不會白走」，且可點擊進入建立／加入團隊
- [ ] 結束記錄先顯示計算轉場（至少 1.2 秒、最長 3 秒），再進摘要
- [ ] 摘要顯示本次步數、距離、減碳量、存到的點數
- [ ] 當天第一次存滿時顯示達標慶祝，同一天不重複（`M4`）
- [ ] 今日足跡在點數卡最下面顯示一行「已連續 N 天走滿 6,000 步・再 N 天得走路犒賞券」；0 天時整行不顯示；某天未達 `P3` 隔天歸零（`P9`）
- [ ] 連續第 7 天存滿時，在同一個達標慶祝裡發放堅持一週的 $50 犒賞券，不另跳畫面；之後天數照常往上加，下一張券的倒數重新算 7 天（`P9`）
- [ ] 訊號弱時顯示提示但不中斷記錄
- [ ] 記錄中切到背景或鎖定螢幕，路線與步數持續記錄
- [ ] 記錄途中網路中斷時照常記錄（GPS 不需要網路），步數與軌跡先存在本機；恢復連線後自動補傳，點數與團隊進度不重複計算（`D1`、`D5`）
- [ ] 使用者拒絕定位權限時，點數與團隊步數照常累積；按「記錄這段路線」時顯示 S19 說明頁，說明為什麼需要定位與如何開啟（`M5`）
- [ ] 使用者拒絕健康資料授權時，今日足跡顯示授權說明與前往設定，不顯示 0 步（`M5`）
- [ ] Demo 假資料（步數與示範路線）在畫面上標示為展示資料（`M2`）
- [ ] 同一天重複同步步數，點數與寶箱資格不重複發放（`D1`）
- [ ] 網路斷線時今日足跡照常顯示步數，點數卡提示連線後自動入帳；點數同步自動重試 3 次仍失敗才顯示「再試一次」
- [ ] 第一次載入顯示骨架屏；有上次的資料時先顯示舊數字並標示「更新中」，不閃成空白
- [ ] 距離下一點或存滿不到 100 步時，提示句寫「再走幾步」，不出現「約 0 分鐘」
- [ ] 每筆獎勵事件記錄 `rule_version`（`D2`）
- [ ] 存滿 3 點後第一次打開今日足跡時跳達標慶祝；記錄中存滿則在摘要後跳；不在 yoxi 首頁跳（`M4`、決策 #105）
- [ ] 走到一半搭車時，行程結束回到首頁，首頁小卡提示「剛剛走的 N 公里記下來了」，點下去看那段路的摘要（`M1`、決策 #106）

### 6.2 開箱與券

團隊寶箱的開箱互動，以及所有乘車券（犒賞券、邀請券，與 yoxi 既有的優惠券）共用的規則。團隊寶箱的獎項全部是點數，不發券（決策 #100）。今日寶箱已移除（決策 #76）；1.0 不另發招待券（決策 #77）。

- [ ] 開箱為長按蓄力：按住 0.8 秒後開啟，轉動期間不可重複點擊
- [ ] 獎項必須先寫進後端再開始轉動，不是轉完才決定
- [ ] 系統開啟「減少動態」偏好時，蓋子、震動與轉輪全部略過，但獎品與標語保留淡入（不位移）
- [ ] **開箱畫面不顯示獎項清單**；獎項與機率放活動規則頁（`R1`、`R2`）
- [ ] 券面顯示面額、效期（`R7`）與最低車資門檻（`R6`）
- [ ] 券面與列表的效期寫絕對時間（「9 月 27 日到期」），不寫相對時數
- [ ] 券存入優惠券列表，過期自動失效並標示
- [ ] 寶箱可以開、還沒開、沒過期時，首頁小卡與今日足跡團隊列的說明行改為「團隊寶箱可以開了・M 月 D 日前」（紅點 ＋ 灰字）；開完或過期就換回（決策 #103）
- [ ] 開箱鈕寫「長按開箱」並附「按住不放，就會打開」；只點一下時給提示、不跳對話框；大字好讀模式與螢幕閱讀器開啟時改為點一下就開（決策 #108）

### 6.3 團隊

- [ ] 未加入團隊時，入口顯示建立或加入
- [ ] 建立團隊時彈出取名面板，預設填好「（使用者名字）的團隊」，上限 12 個字；欄位清空時按下提示「幫團隊取個名字」（決策 #107）
- [ ] 建立團隊後可產生邀請連結，用連結加入不需隊長同意（`T9`）；連結不設時間限制，滿 5 人、解散或重新產生後失效（`T14`）
- [ ] 受邀人還沒有 yoxi：連結先開網頁說明頁（誰邀請、哪個團隊、新戶獎勵、推薦碼），下載註冊後進「加入團隊」頁；**Demo 的推薦碼與團隊邀請由展示資料直接帶入**
- [ ] 受邀人已經有 yoxi：連結直接開 App 的「加入團隊」頁，顯示誰邀請、團隊成員、本週進度與三條規則，按「加入團隊」才加入
- [ ] 已經在別的團隊時，說明「一個人一次只能在一個團隊，每週可以換一次」與步數留在原團隊，由使用者選擇換或留（`T12`、`T13`）
- [ ] 團隊只有 1 人時不啟動週挑戰，顯示「再邀 1 人就能開始挑戰」，但**步數仍照常累計**（`T1`）
- [ ] 第 2 位成員加入時挑戰啟動；之後週中有人加入，目標仍為 `T2` 不打折，**加入前累計的步數保留**（`T6`）
- [ ] 挑戰啟動後顯示本週進度（全隊步數 / `T2`）、剩餘天數與還差步數
- [ ] 未滿 5 人時顯示「目前 N 人，每人每天約需 N 步」與「再邀 N 人，每人每天只要 N 步」，旁邊放邀請成員入口；文案用邀請語氣，不寫「人太少、達不到」這類責備說法（決策 #80）
- [ ] 成員列說明行顯示本週貢獻、右側顯示今日步數；今日步數最高者名字旁加「今日第一」小標；點進成員後可「幫他加油」，每人每天一次（`T10`）

- [ ] 每人計入團隊的步數**不設每日上限**，走多少算多少（`T5`）
- [ ] 週一 06:00 結算上週（週一至週日產生的步數，含補傳）；達標則每位成員各得一次團隊寶箱（`T4`、`T7`、`T8`）

### 6.5 AI 情境推薦

- [ ] 差 `A1` 步以內，且非雨天、所在縣市無高溫資訊燈號時，顯示鼓勵卡，按鈕為「今天先到這」／「好，繼續走」

- [ ] 符合 `A2` 時顯示雨天卡：同回程卡，標題改寫小時級降雨時間（「傍晚可能下雨，趁還沒下先搭車回去？」），不發券

- [ ] 回程卡、雨天卡每趟各最多 1 次；拒絕定位或網路斷線時不出現，鼓勵卡照常

- [ ] 按「搭車回去」後，下車點帶入**出發點**，犒賞券與點數折抵一併帶入，進入叫車確認頁
- [ ] 上車後走路記錄自動結束並結算（`M1`）
- [ ] 推播頻率不超過 `A4`
