## 閱讀說明

- 每一項（F1、F2…）各自獨立，可以分開做。**沒有列在這份說明裡的地方不要動**
- 文案裡的 N、M、X 都要換成實際的數字；步數加千分位（例：1,000）
- 「現在」欄寫的是 10/9 在 Demo 上看到的文字。如果程式裡的文字跟這裡寫的不一樣，請先回報，不要自己猜要改哪一句

### F1 步數旁邊的鉛筆加上文字

**問題**：輸入步數的入口（`.app-steps-open`）現在只有一支鉛筆圖示。第一次用的人不知道步數要自己輸入，後面全部玩不到。遊玩指南最下面寫的是「點地圖上的『鉛筆』」，要先看過指南、再回頭找那支鉛筆才知道。

**改法**（見 `36-demo-steps-input-entry.png`）

- 鉛筆圓鈕改成膠囊形小按鈕：鉛筆圖示 ＋ 文字「輸入步數」。白底、高 32、左右內距 12、字 13px 粗體墨藍，保留現在的淡陰影
- 位置：地圖上、步數大數字的正下方，置中
- 遊玩指南最下面那句，「點地圖上的「鉛筆」」改成「點步數下面的「輸入步數」」，跟按鈕上的字一致。其他不變

### F2 拿掉紅色光暈

團隊頁的「組建隊伍」和「邀請成員」（只有自己、招募中時）還有 `.yo-claim-glow`。兩顆都拿掉，按鈕本身不變。

### F3 四句話改成白話

### F5 只有自己一個人時，寶箱分頁的文字

**問題**：有隊伍但還沒成團（只有自己）時，團隊頁寫「成團後才開始累計團隊步數」，寶箱分頁卻寫「本週還差 30.0 萬步・剩 N 天」。兩頁互相矛盾。

**改法**：這個狀態下，寶箱分頁那張卡改成

- 標題：團隊寶箱
- 說明：還沒解鎖・再邀 1 人成團，才開始累計步數
- 一顆「前往團隊」（跟沒有隊伍時那顆一樣）
- 「週一 00:00 結算」這一行不顯示

已成團之後維持現在的寫法。

### F6 開完寶箱後那張卡的排版

**問題**：開過寶箱後，寶箱分頁的卡片下半部，左邊「接下來走的步數照樣算進個人點數」和右邊「活動說明」擠在同一行，「活動說明」被折成兩行（活動說／明）。

**改法**：兩者各佔一行。說明在上、靠左；「活動說明」在下、靠右。

### F7 地圖改成灰藍色

**問題**：地圖用的是 OpenStreetMap 預設配色（黃色道路、綠色公園、粉紅區塊），顏色多，跟品牌的紅色和墨藍互搶，壓在上面的步數大字不好讀。

**改法**：不換地圖來源，在地圖的圖層上加濾鏡，變成淡淡的灰藍色。

```css
.leaflet-tile-pane {
  filter: grayscale(1) sepia(0.25) hue-rotate(175deg) saturate(1.6) brightness(1.08) contrast(0.88);
}
```

只套在圖層（`.leaflet-tile-pane`），不要套到整個地圖容器，不然上面的步數、位置標籤和按鈕也會跟著變色。這組參數是 10/9 直接在 Demo 上試出來的，可以再微調。

### F8 團隊頁說明「加入之後走的步數才算」

**問題**：加入隊伍之前走的步數不會算進團隊，但畫面沒有講。10/9 實測：個人 3,000 步時加入隊伍，團隊頁我那一列是「本週 0 步・0 步 今天」；個人加到 4,000 步後，那一列是「1,000 步 今天」。同一個人、同一天，步數頁寫 4,000、團隊頁寫 1,000，使用者會以為步數不見或算錯。

規則本身不用改，只要講清楚：

- 「成員（N 人，最多 5 人）」那一行下面加一行小字（13px `#778AA4`）：加入隊伍之後走的步數才會計入
- 加入成功的當下跳一則 Toast：「加入了！從現在開始走的步數會算進團隊」
- 成員列右邊數字下面的「今天」，在加入當天改成「加入後」。做起來麻煩的話這一點可以不做，前兩點要有

### F15 按下「領取」之後跳一則提示

**問題**：在「今日」按「領取 N 點」之後，只有圓變勾勾、右上的數字增加、按鈕消失，沒有任何一句話說領到了；按鈕消失後下面的內容還會往上跳，使用者不確定自己按到了沒。「昨日」的補領也一樣。

**改法**：領取成功時跳一則 Toast。

- 樣式：深灰底 `#3C4C60`、白字 14px、膠囊形（圓角全圓）、左右內距 16、上下 10，水平置中，位置在底部分頁的上方
- 顯示 3 秒後自動淡出；顯示期間不擋操作
- 文字：

| 哪裡 | 文字 |
|---|---|
| 「今日」按「領取 N 點」 | 已領取 N 點，可以折 $N 車資 |
| 「昨日」按「補領 N 點」 | 已補領 N 點，可以折 $N 車資 |

（1 點折 1 元，所以兩個 N 相同。）

### F9 還沒有步數時，卡片裡放一顆大按鈕

見 `36-demo-steps-input-entry.png` 左邊。**只在「今日」分頁、今天的步數是 0 時出現。**

- 一顆實心按鈕（樣式同「領取 N 點」）：輸入今天的步數

### F10 「組建隊伍」按下去先確認

**問題**：現在一按就建立隊伍，沒有確認。點錯就多一支隊伍。

**改法**：按下去先跳一個確認視窗，樣式沿用現有的確認視窗（改隊名用的 `.confirm-dialog`）

- 按「建立隊伍」才真的建立；按「先不要」或關閉視窗，什麼都不發生

### F11 開過寶箱之後的說法

見 `Q1-after-opening-chest.jpg`（10/9 的截圖）。

**問題**：10/9 測試時，隊伍一達標，獎勵頁的寶箱分頁就出現「團隊寶箱可以開了」，開了、抽到 2 點。開完之後，同一張卡寫的是「本週達標了！週一 00:00 後，每人可以開一次團隊寶箱」。才剛開完，畫面卻說下週一才能開，使用者會搞不清楚自己到底開過了沒。

**動手之前，請先問 Ken 這一題**（這是規則，不能自己假設）：

> 團隊寶箱是「達標的當週就能開」，還是「下週一 00:00 之後才能開」？

依他的答案做：

| Ken 的答案 | 達標、還沒開 | 開過之後 |
|---|---|---|
| 達標當週就能開 | 維持現在的「團隊寶箱可以開了」和「開團隊寶箱」按鈕 | 標題「這週的寶箱開過了」，說明「抽到 N 點・下週一重新開始累計」 |
| 下週一才能開 | 標題「本週達標了！」，說明「下週一起每人可以開一次」，不放開箱按鈕 | 同上：標題「這週的寶箱開過了」，說明「抽到 N 點・下週一重新開始累計」 |

原則：**開過了就說開過了**，不要再寫「可以開一次」。

### F12 團隊頁達標之後

**問題**：達標的訊息出現三次（「已達標」標籤、「本週已達標，接下來走的步數照樣算進個人點數。」、「本週已達標：10/08 09:00・寶箱資格 3 人」），最後一句「您已取得本週寶箱資格，可到獎勵頁開箱。」只是文字、不能點。

**改法**

- 保留進度條下的「已達標」標籤
- 下面那幾段合成一段：「達標了！N 個人都可以開寶箱」
- 寶箱可以開、而且我還沒開時，放一顆實心按鈕「去開寶箱」，點了到獎勵頁的寶箱；已經開過就不放按鈕，寫「這週的寶箱開過了」
- 拿掉「10/08 09:00」「寶箱資格」這兩個說法

### F13 通知

**問題**：內容是「已獲得推薦獎勵，請至「獎勵 > 獎勵券」查看」。沒有講拿到什麼，還要使用者自己照路徑走過去。

**改法**

- 文字寫出拿到什麼，例：「拿到 2 張 $50 推薦獎勵券」「拿到 1 張 $50 乘車獎勵券」「團隊寶箱可以開了」
- 每一則下面加一行時間（今天／昨天／10/8）
- 整則可以點，右邊放一個箭頭讓人知道可以點。點了關掉通知面板，並到對應的地方：

| 通知的內容 | 點了去哪裡 |
|---|---|
| 拿到獎勵券 | 獎勵頁的「獎勵券」分頁 |
| 團隊寶箱可以開 | 獎勵頁的「寶箱」分頁 |
| 有點數可以領、昨天的點數可以補領 | 步數頁的「今日」或「昨日」分頁 |

- 其他種類的通知比照同樣的寫法：直接講發生了什麼、數量多少，不要寫「請至某某頁查看」
- 只有一則通知時，不顯示「全部已讀」

### F16 搭車之後：實際步數的說明換位置，「再走 N 步」改用實際要走的步數

見 `40-demo-ride-note-position.png`（左邊現況，右邊要改成的樣子）。

**問題一：說明看不清楚。** 搭車後，地圖上的大數字下面有一行「搭了 yoxi，步數變 1.5 倍・實際走了 N 步」，直接壓在地圖上、沒有底色，讀不到。

**改法**

- 地圖上那一行拿掉。地圖上只留步數大數字和「輸入步數」
- 改放在卡片裡、進度條刻度數字（0／2,000／4,000／6,000）的正下方、狀態句的上面：

> 實際走了 **2,000** 步，搭 yoxi 變 1.5 倍

- 樣式：13px、灰色 `#778AA4`、靠左、單行；只有實際步數的數字用墨藍 `#0B1F38` 粗體
- 間距：距上方刻度數字 12，距下方狀態句 16
- 只在今天搭過車、而且實際步數大於 0 時顯示；沒搭車或實際步數是 0 時，整行不出現

**問題二：「再走 N 步」的數字對不上。**

搭車之後，使用者接下來走的每一步也會乘 1.5。但畫面上的「再走 N 步」現在是用加成後的步數算的，會叫使用者多走。

例：實際走了 2,000 步，搭車後算 3,000 步。下一個門檻是 4,000，畫面寫「再走 1,000 步」。但使用者實際只要再走 667 步（667 × 1.5 ≈ 1,000）就到了。而且「實際走了 2,000 步」和「再走 1,000 步」放在一起，加起來是 3,000，跟門檻 4,000 對不上。

**規則**：畫面上所有「再走 N 步」，N 一律是**使用者實際還要走的步數**。

```
差距 = 下一個門檻 − 目前的步數（加成後）

今天沒搭車：N = 差距
今天搭過車：N = 差距 ÷ 1.5，無條件進位到整數
```

| 實際走了 | 搭車 | 畫面上的步數 | 下一個門檻 | 差距 | 「再走 N 步」的 N |
|---|---|---|---|---|---|
| 3,000 | 沒有 | 3,000 | 4,000 | 1,000 | 1,000 |
| 2,000 | 有 | 3,000 | 4,000 | 1,000 | 667 |
| 3,000 | 有 | 4,500 | 6,000 | 1,500 | 1,000 |
| 1,000 | 有 | 1,500 | 2,000 | 500 | 334 |

適用的地方：

- 「今日」卡片裡的狀態句和它的小字（「再走 N 步，就可以領 1 點」「再走 N 步，就可以再領 1 點」）
- F14「本週」點今天時的小字（「再走 N 步就達標」，門檻是 6,000）

其他數字不變：地圖上的大數字、進度條、門檻、是否達標，都照加成後的步數。

### F17 還沒有步數就按「模擬一趟」

見 `41-demo-ride-zero-steps.png`。

**問題**：今天的步數是 0 時按「模擬一趟」，一樣會跳出慶祝彈窗。0 步乘 1.5 還是 0，彈窗卻顯示「0 → 0 步」，使用者不知道發生了什麼。

**為什麼不是直接擋掉**：0 步時不讓人按「模擬一趟」是另一種做法，但沒有採用。原因有兩個：

- 實際使用時，早上先搭車、之後才走路是很正常的順序，加成本來就算一整天，沒有理由擋
- 第一次打開的人很可能先按這顆，按不下去反而會卡住

所以彈窗照樣跳，只換內容：不顯示沒有意義的「0 → 0」，改成講接下來會發生什麼，並用按鈕把人帶到下一步（輸入步數）。這樣這一下沒有白按。

**改法**：今天的步數是 0 時按「模擬一趟」，彈窗內容如下（車子圖示、標語「Nice Ride!」、撒花、動畫都跟原本一樣）：

| | 原本（有步數） | 步數是 0 時 |
|---|---|---|
| 標題 | 今天的步數變 1.5 倍 | 今天走的步數都會變 1.5 倍 |
| 數字那一行 | 5,000 → 7,500 步 | 不顯示 |
| 小字 | 多了 N 點可以領 等 | 還沒有步數，先輸入今天走了幾步 |
| 按鈕 | 領取 N 點／知道了 | 輸入步數 |

- 按「輸入步數」：關掉彈窗，直接打開輸入步數的視窗（跟步數旁邊那顆「輸入步數」開的是同一個）
- 搭車照樣算完成：「搭一趟 yoxi」那一列變成「已完成」，之後輸入的步數會乘 1.5
